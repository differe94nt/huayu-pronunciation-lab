# v2 —— 說明

v1 的兩個單檔網頁（`../index.html`、`../workbench.html`）**沒有動**，可以繼續用。
v2 是另一套，解決四件 v1 做不到的事：

| | v1 | v2 |
|---|---|---|
| 改內容 | 進 HTML 找 JS 陣列 | 改 `content/*.md` |
| 音檔 | 只能放 `audio/` 資料夾 | 雲端硬碟 → 內嵌播放器；本機模式需明確設定 |
| 收答案 | 只存在學生自己的瀏覽器 | 同步到 Google 試算表，老師有即時看板 |
| 預測的可信度 | 一個聲明 | 逐條證據等級 + 假設審核 + 拿學生資料回頭比對 |

---

## 先跑起來

**不能直接雙擊開檔。** v2 會去讀 `content/` 裡的 `.md`，瀏覽器不允許 `file://` 這樣做。

```bash
cd huayu-pronunciation-lab
python3 -m http.server 8000
```

然後開 <http://localhost:8000/v2/>。

發布到 GitHub Pages 之後就沒有這個限制。

| 網址 | 給誰 |
|---|---|
| `v2/index.html` | 學生：聽問查教工作台 |
| `v2/workbench.html` | 學生：華語糾音工作台 |
| `v2/live.html` | 老師：上課投影用的即時看板 |

## 要改東西

### 改內容 → `content/`

| 想改什麼 | 改哪個檔 |
|---|---|
| 組別、母語、音檔對照 | `groups.md` |
| 六個面向底下的現象標籤 | `levels.md` |
| 母語 × 華語音韻對照表 | `contrast.md` |
| 糾音知識庫（診斷／操作／最小對立對） | `kb.md` |
| 四步驟、三分類、六角色、九點建議、評分規準 | `course.md` |
| 示範學習者的預測檔案 | `learners.md` |
| 語料庫清單 | `corpora.md` |
| 給 AI 的任務指令全文 | `prompt.md` |
| 解讀手冊 | `manual.md` |
| 假設審核（文獻查核結果） | `evidence.md` |
| 學生資料與預測之間的對照鍵 | `tagmap.md` |

每個檔案最上面都有 `<!-- 註解 -->` 寫著格式規則。基本上就是：

- `##` 開一個新區塊
- Markdown 表格就是資料表，**欄位名稱不要改**（程式靠它認欄位）
- `- 鍵：值` 的清單會變成欄位
- `>` 引言會變成綠色提示框

改完存檔、重新整理瀏覽器，就看得到。沒有建置步驟。

## 改字的時候，哪些地方不能動

`content/*.md` 裡的**內文**隨便改，但有三種東西是程式用來認位置的，改了那一塊資料就會整塊讀不到
（畫面上會變空白，不會報錯，所以特別要小心）：

### 1. `##` 區塊標題

這 13 個標題是程式查找的錨點，**文字要一模一樣**：

| 檔案 | 不能改的 `##` 標題 |
|---|---|
| `groups.md` | 組別、說明 |
| `kb.md` | 條目 |
| `course.md` | 四個步驟、三分類、六人角色、對課程邏輯的建議、評分規準、來源層級 |
| `tagmap.md` | 比對鍵、母語別名、外部基準線、怎麼讀比對結果 |

`levels.md`、`contrast.md`、`learners.md`、`corpora.md` 的 `##` 標題**可以改**——
它們本身就是資料（面向名稱、母語名稱、學習者名稱、語料庫名稱）。
但改 `contrast.md` 的母語名稱時，要跟 `groups.md` 的「母語」欄一致，否則對照表會查不到。

### 2. 表格的欄位名（表頭那一列）

程式用欄位名取值，不是用第幾欄。所以**欄位名不能改，順序可以隨便換**。
每個檔案最上面的 `<!-- 註解 -->` 都寫了它自己的欄位。

### 3. 「比對鍵」欄的值

`levels.md`、`learners.md`、`tagmap.md` 三個檔案的比對鍵必須對得上，
實證比對才連得起來。要新增一個比對現象，三個檔案都要加。

### 可以放心改的

- 所有敘述文字、表格儲存格內容、`>` 引言
- `manual.md`、`evidence.md`、`prompt.md` **整份都可以自由改**，它們是純文字，沒有結構限制
- `learners.md` 的學習者名稱、程度、例子、偏誤來源等等

### 改完一定要跑一次

```bash
python3 -m http.server 8000
# 開 http://localhost:8000/v2/_selftest.html
```

最後一行要是「全部通過」。它會檢查欄位是否齊全、比對鍵是否對得上。
畫面突然變空白，八成就是上面三件事之一改到了。

### 改設定 → `config.js`

班級代號、音檔來源順序、後端網址、要不要強制填分母、規律成立門檻，全部在這一個檔案裡，每一項都有註解。

### 改樣式 → `assets/base.css`

配色在最上面的 `:root`。深色模式有兩個對應區塊（`@media (prefers-color-scheme:dark)` 與 `[data-theme="dark"]`），**三處要一起改**。

### 改完怎麼確認沒改壞

開 `v2/_selftest.html`。它會把 `content/` 全部讀一遍、檢查欄位、跑一次比對，然後印出結果。
最後一行應為「全部通過」；這只驗證內容、儲存與比對，不驗證 Google 部署或播放。改完 `.md` 之後跑一下，比在正式頁面上大海撈針快。

（這頁會暫時寫入幾筆假資料到 localStorage，跑完自己清掉，不會影響學生的資料。）

### 其他 `assets/*.js`

這些是程式，正常情況不用動：

| 檔案 | 做什麼 |
|---|---|
| `md.js` | 把 `.md` 讀進來、拆成區塊、轉成 HTML |
| `data.js` | 把區塊變成頁面要用的資料結構 |
| `audio.js` | 決定音檔從哪裡來，產生播放器 |
| `store.js` | 資料存到 localStorage／Google 試算表／Claude 資料庫 |
| `compare.js` | 把學生的標註跟預測放在一起算 |
| `viz.js` | 五度制調型、熱區條、比對條 |

## 實證比對怎麼運作

這是 v2 最主要的新東西。鏈路是這樣：

```
學生標註（index.html）
  標籤 ──levels.md 的「比對鍵」──▶ 比對鍵
                                      │
示範學習者預測（workbench.html）      │
  偏誤項 ──learners.md 的「比對鍵」──▶ 比對鍵
                                      │
                                      ▼
                              同一列，畫在一起
```

所以**新增一個要比對的現象**，要動三個地方：

1. `tagmap.md` 加一列，定義這個鍵叫什麼；
2. `levels.md` 的某個標籤填上這個鍵；
3. `learners.md` 的某個偏誤項填上同一個鍵。

三邊對上了，比對面板才會把它們畫成同一列。

### 兩邊的單位不一樣，所以不硬湊

| | 單位 | 怎麼來的 |
|---|---|---|
| 預測 | 序位（強 3／中 2／弱 1／優勢 0） | 對比分析推論，不是測量值 |
| 觀察 | 有分母 → 出現率；沒分母 → 說話人覆蓋率 | 學生的標註 |

畫面上兩條並排，但**不會相減、不會算差距**——那會假裝它們是同一個尺度。

真正可以下判斷的是兩件事：

- **排序一致度（Spearman ρ）**：預測排在前面的，是不是實際上也比較常見。只說明排序像不像，不說明預測「對不對」。配對項目少於 4 個就不給數字。
- **命中／落空／預測之外**：這三個標籤才是報告裡真正好寫的東西。「預測之外」尤其值得追。

### 分母

`config.js` 的 `requireDenominator` 預設是 `true`，學生每筆觀察會多一個欄位：
「這個音（調、規則）在這段語料裡本來有幾次機會出現」。

沒有分母就只能說「我們注意到這個」，不能說「出現率是多少」。
關掉它（改成 `false`）介面會清爽一點，但比對面板就只能用覆蓋率，
而且「重現矩陣」的出現率欄位會全是 `—`。

## 資料存在哪裡

依 `config.js` 的設定，三選一，網頁會自己判斷並顯示在右上角：

| 右上角顯示 | 意思 |
|---|---|
| 灰色「只存在這台電腦」 | `backendUrl` 是空的。資料只在 localStorage，換電腦或清瀏覽器就沒了 |
| 綠色「已同步到試算表」 | 存到 Google 試算表，老師的看板看得到 |
| 黃色「離線——資料仍存在本機」 | 後端一時連不上。資料沒掉，恢復連線後再按一次儲存即可 |
| 綠色「全組即時同步」 | 這一份發布在 Claude Artifact 上，用的是 Claude 的共享資料庫 |

不管哪一種，**都會同時寫一份到 localStorage**，所以斷線不會掉資料。

## 資料存取範圍

學生頁面的介面以自己的組別與彙總統計為主，但這不是 API 權限限制。
目前後端的 `rows`、`class` 與寫入操作沒有登入或組別權限驗證；
知道後端網址及班級代號的人可以讀寫各組資料。音檔密碼只保護音檔對照表。
`live.html` 也沒有教師登入驗證，隱藏網址不能保密。

請先使用不具識別性的資料；若需保護學生姓名或逐筆紀錄，必須另加帳號與角色權限。
詳細邊界與 Drive 連結分享限制見 [backend/SETUP.md](backend/SETUP.md)。
